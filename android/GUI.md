# The launcher's look, and how to add to it

The launcher is built in Java code (no layout XML): `MainActivity` (Home and Settings), `GameSettings` (a game's page), `SidePanel` (the in-game panel), with the building blocks in `Ui`. This page is the design the screens follow, and the checklist for adding a screen, a row or a language. The details of languages are in [android/README.md](README.md#languages).

## The design (keep it; change it only on purpose)

The look is the Nintendo Switch 2 home screen with banana-yellow accents.

- **Home** is one sideways row of full-bleed artwork tiles with no text on them. The selected tile grows (1.2×) with a banana ring and is centred when the focus or a swipe moves to it. A game that is not Ready shows a state veil on its tile (a dim layer, the state in words, a thin moving bar while something is being made; the quick shader check shows as the small corner ring with its progress, the game stays playable; a Prepare job is the big ring on the tile in every state: the arc for running, going round while it waits, still with II when paused, full red with ! when failed, and a tap opens the job's sheet with the steps, the error and the buttons: `MainActivity.workTick`, `Ondevice.tileState`). The Prepare card is never on Home: `Ondevice.attach` builds it but does not add it, so it shows only in the sheet (`Ondevice.sheet`, its buttons take the pad's focus like any dialog), and the sheet opens by itself when a job newly needs a tap (it failed, or a heat pause asks Go on anyway: `Ondevice.Panel.needsTap`), never while a job just runs. The questions of a new Prepare are dialogs of their own. Home never scrolls up or down (`Ui.FixedScroll`).
  - Top left: the logo alone. Top right: a dock pill with the user's letter (opens Users), the player wiki and Settings, with tooltips and the same size as the logo.
  - Add game is a round yellow button floating at the bottom right. It is always there, in every layout, also with no game (then Home is one line, "Add a game to start", the button has the controller's focus and the hint bar says A Add game); there is no welcome screen (#381: the button had been hidden there). The background is plain by default; drifting bananas or the player's own picture are choices in Settings › Appearance.
  - **A game's options**: a long press on a tile (Hold X, or Y, on a controller: `MainActivity.dispatchKeyEvent`) opens a pad-focusable menu: **Move**, **Set cover image** (and **Reset cover** when it has one: `CoverUi`) and **Remove game…** (a tile being prepared keeps its job sheet on a long press). **Move** is a reorder mode (`MainActivity.startMove`): the game is lifted; the D-pad moves it (the grid: all four directions), a tap on another game's place moves it there, A or a tap on the lifted game puts it down, B or Back puts it back where it was. The order is a list of game ids (title ID and pack, `GameOrder`) in `Prefs.gameOrder`; a game not in it goes last.
  - **Home layout** (Settings › Appearance › Home layout, `Prefs.homeLayout`, `HomeLayout`): the sideways row above is the default. **Grid with names** puts each tile with its name under it (two columns upright, more on a wide window) and **List** is one row per game (a 56 dp cover, the name, and the version and state as a second line). Both scroll up and down by themselves (Home as a page still does not). The tile is the same view in all three (`MainActivity.artTile`); in the grid and the list it sits in a `HomeLayout.Item` that takes the focus, tap and long press for it, so the banana ring, the controller (Y) and the long press menu work as on the row, and the selected tile does not grow. A list cover is too small for the veil's words and bar: it keeps the ring (Prepare) and the small corner ring, and the state is in the row's second line (`HomeLayout.caption`).  The options menu and Move work the same in all three.
  - **Remove game** (the game page › Storage, and the options menu: `GameDelete`): one question names what goes: the list entry, the game's pack and shader libraries when they are in the app's storage, its Prepare work folder, logs and DLC links (`StorageScan.gameData`, the set of Settings › Storage › Remove game data), and the copy of the game in the app's storage when it is one (not when a save folder lies inside it). Never the player's own dump folder or a pack folder elsewhere, and never a save folder (`StorageScan.delete` refuses every folder in `Roots.saves`, the deleted game's included). It refuses while a game runs or the game is being prepared. The player's own cover picture goes with it (`Covers.delete`). **Remove from list** stays beside it and deletes nothing.
  - **Hint bar** (`HintBar`, bottom centre of every page): small chips with their words, for what works now: on Home with a controller on a game "A Open  X Options (hold)", with touch "Hold a game for options", in Move mode the D-pad, A and B (touch: a line on tapping), on the game page and Settings "A Select  B Back". The chips are letters in banana plates (the button-icon font `nintendo_ext.ttf` is made for the games' packs and is not in the launcher). Dialogs and menus (`PadFocus`) have no bar.
  - A tall window (a phone upright) shows one big tile centred in the free space, with no text under it (the tile's accessibility label carries the name), and a swipe settles on a tile (`MainActivity.tileRow`).
- **A game's page**: a top bar (Back, the game's picture, its name and version). A wide window (width of 600 dp or more) has a left column (Play, the tabs) and a right pane that scrolls on its own (`MainActivity.newPane`). A narrow window has Play as a round button in the bar, a tab strip and one scrolling column. The shader setting is one small row that opens a dialog. While the quick shader check of a game runs or waits (`Ondevice.sampling`), its page shows a **Checking shaders** card under the tabs (the check's words, a bar, **Skip**: `GameSettings.shaderCheckCard`), and after a skip a small **Shader check skipped** row whose tap checks again (the 7 days' memory is the check's, `SampleQueue.skipped`).
- **Cover image**: a game's page has a **Cover image** row (Game options) with **Set cover image** and, when one is set, **Reset cover**. The picture comes from the system picker (`ACTION_OPEN_DOCUMENT`, no storage permission; the grant is for the one picture), then the crop screen (`CropActivity`): the picture moves under a fixed square frame (Home's tile and the game page's picture are both square, so one frame covers both) with a finger and a pinch, or with a controller (D-pad or left stick moves, L1 / R1 or the triggers zoom, A confirms, B cancels). The crop arithmetic is `CropMath` (JVM-tested). The result is cut at most 1024 px on the long side and kept as a JPEG in the app's private `files/covers/`, one per game id (`GameOrder.id`: title ID and pack) by `Covers`; nothing goes into the game's dump, pack or save folders. Every place that draws a game's art asks `Covers.show(tile, game)` first and skips the game's own icon (`GameMeta`) when it says true; a new place that draws the art must do the same. Whoever removes a game's entry from Home calls `Covers.delete(context, game)` (or the id) so its cover goes too.
- **Settings**: a wide window has a left list of sections (cut at `Ui.section` labels) and a right pane. A narrow window has the list of sections first and one section at a time under its own header with Back.
- **Colours and shape**: light grey page and white cards in the light theme, a neutral dark set in the dark theme (`res/values/colors.xml`, `values-night`), 24 dp card corners, 22 dp tile corners, compact rows, the banana ring (`bn_banana_deep`) as the only focus highlight. The default Android focus highlight is off (`MainActivity.noFocusTint`): with a controller it would tint the whole screen.
- **Sounds** (`UiSound`): a tick when the focus moves, a chirp on a real tap only (never on a drag), an off switch and a custom sound. **Theme** can be forced light or dark (`NxApp.applyTheme`).
- **The "Building shaders" label** in a game is small, see-through and at the very top edge (`GameActivity.layerShow`); Settings › **Building shaders label** (and the same row in the in-game menu's General section) picks Off, Number only (default) or Full text; a paused build is said in all three.
- **The in-game menu** is one rounded drawer sliding in from the left over the running game: a pinned side menu (the game's name, Pause or Resume, the four sections, Stop) and, once a section is picked, that section's rows in a column to its right inside the same drawer. No tab bar: the side menu is the navigation, Back goes one level up. Its rows are the launcher's rows. A profile option marked `live` (game.tsv `option ... live`, e.g. Ocarina of Time's Keep cave walls) is a switch on the Performance section that applies at once (an `env NAME=1` or `=0` line in ctl.txt, `SidePanel.pushLiveOption`) and is stored per game like the Game settings toggle, so it holds at every start; restart options are in Game settings only.

## Adding a screen, a row or a dialog

1. **Text goes into resources.** Add the English to `res/values/strings.xml` under a key for its screen (`home_`, `settings_`, `game_`, `prepare_`, `ready_`, `err_`, or `common_` for words several screens share) and read it with `Tx.s(R.string.key)`. A number inside a sentence is a `%1$s` argument; a counted noun is a plural (`Tx.n(R.plurals.key, n)`); a list of choices is a string array (`Tx.arr(R.array.name)`). Never build a sentence by gluing pieces: word order differs between languages.
   A class the JVM tests compile without Android (`PrepareText`, `Job`, `Readiness`, `Profile`, `Recommend` ...) uses `Words.s("key", "English")` (and `Words.n` for plurals): the English is the fallback the tests see, `NxApp` points `Words` at the same resources, and a test checks that the English in the code equals `strings.xml`. A text held in a constant becomes a method, so a language change shows at once.
2. **Keep logic out of the words.** Do not compare text with English (`equals("Ready")`); compare the state or the key the text came from.
3. **Do not use emoji in strings**; they stay in code.
4. **Run the guard:** `python3 dm/tools/ui_strings.py --check`. It fails on a hard-coded UI literal; what stays English on purpose (the Advanced page, log lines, `[RED]` lines, environment names) is in `dm/tools/ui_strings_allow.txt` with a reason.
5. **Translate it:** the same key goes into every `res/values-<lang>/strings.xml` (`python3 dm/tools/i18n_xml.py export` gives the English as JSON, `write <lang> <file.json>` writes a translation back and checks keys, placeholders and plural forms). A key with no translation shows in English, so a missed one is not a crash.
6. **Layout that survives a longer word:** French, Polish and Turkish run 30 to 50 % longer than English. Use `setMaxLines` with an ellipsis or wrapping, never a fixed width for text; check the dock, the tab strips, the left lists, the tile veil and the in-game menu's side menu.
7. **Right to left (Arabic):** use start and end (`setMarginStart`, `setPaddingRelative`, `Gravity.START`), never `Gravity.LEFT`, `leftMargin` or `rightMargin` in a redesigned screen (a test checks it). The in-game overlay and the on-screen controls keep their pixel positions on purpose.
8. **Both orientations:** a screen has a wide form (width of 600 dp or more) and a narrow one. Check Home, the game's page and Settings upright and sideways.
9. **Focus and a controller:** every control that takes a tap must take the focus (`setFocusable(true)`) and show the banana ring (`MainActivity.ring`), and a page must be usable with the D-pad alone (`PadFocus`).
10. **Tests:** the source-check tests read `Tx.s(R.string.key)` as its English text through `dm/tools/tests/javatext.py`, so a test can look for a row's English title; it patches file reading only between `javatext.install()` and `uninstall()` in a test module, so it never changes another test. Run the Python tests in `dm/tools/tests` (`test_android_*.py`, `test_ui_strings.py`, `test_docs.py`).

## Adding a language

1. Make `res/values-<lang>/strings.xml` (the tool in step 5 above writes it), marked "machine translated, unreviewed" until a native speaker has checked it.
2. Add its line to `res/xml/locales_config.xml`, its own name to `res/values/languages.xml`, and a line to `Languages.LIST`.
3. Run `python3 dm/tools/i18n_xml.py check` and the tests, then look at the language on a phone: the longest words (tabs, dock, left lists), plurals, and for a right-to-left language the mirroring of Home, Settings and the game's page.
